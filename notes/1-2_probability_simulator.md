## 한 줄 요약 (내 말로)

> 음 확률은 대충 생각하면 알것도같은데 막상 이걸 수식이나 식으로 적으려면 어렵네 그래도 뭔가 독립인 사건들이 서로 직렬로 있을때는 서로의 확률을 곱하면 최종 확률 예를들어 가동률을 구할 수 있다

## 오늘의 질문과 결과

가동률 99%인 서버 5대가 모두 살아 있어야 돌아가는 서비스, 전체 가동률은 몇 %일까?

| 경우 | 예측 | 시뮬레이션 | 공식 |
|---|---|---|---|
| 서버 5대 (따로 고장) | 0.99를 5번 곱한다 | 0.9506 | $0.99^5 \approx 0.951$ |
| 서버 100대 (따로 고장) | 0.99를 100번 곱한다. 값은 0.9999…로 예상 | 0.3673 | $0.99^{100} \approx 0.366$ |
| 서버 5대가 전원 하나를 같이 씀 | 0.99 | 0.9898 | $0.99$ |

서버 한 대는 한 달(720시간)에 7.2시간 멈추지만, 5대짜리 서비스는 약 35.6시간 멈춘다.

## 핵심 정리

- **확률 = 아주 많이 반복했을 때 일어나는 비율.** 서버를 10분만 보면 살아 있던 비율이 1.0이었고, 20,000분 보면 0.9891이었다. 반복할수록 비율이 한 값에 가까워지는 현상이 **큰 수의 법칙**이다. 이렇게 난수로 많이 반복해서 확률을 재는 방법을 **몬테카를로 시뮬레이션**이라고 부른다.
- **난수로 '99%' 흉내 내기:** 0~1 난수가 0.99보다 작을 확률은 0.99다 (0~1 자에서 0.99까지가 길이의 99%). 코드로는 `rng.random() < p`. 씨앗(seed)이 같으면 같은 난수가 나와서 결과를 다시 만들 수 있다.
- **사건과 $P(A)$:** 사건은 일어나거나 안 일어나는 일이다 ('A = 서버 A가 살아 있다'). $P(A)$는 사건 $A$의 확률이다.
- **확률의 기본 성질 세 가지:**
  1. $0 \le P(A) \le 1$. 비율이니까 0(한 번도 안 일어남)부터 1(매번 일어남) 사이다. 등호가 들어간다.
  2. $P(\text{전체}) = 1$. 일어날 수 있는 일을 전부 모으면 반드시 그중 하나는 일어난다.
  3. 동시에 일어날 수 없는 두 사건이면 확률을 더한다. 겹칠 수 있으면 그냥 더하면 안 된다 (1-4).
- **$A \cap B$ (A 그리고 B):** $A$와 $B$가 둘 다 일어나는 사건. "서버 5대가 모두 살아 있다"는 $A_1 \cap A_2 \cap \cdots \cap A_5$다. 노트북에서는 행마다 `.all(axis=1)`로 셌다.
- **독립:** 한 사건이 일어났는지 알아도 다른 사건의 확률이 바뀌지 않는 것. 독립이면
  $$P(A \cap B) = P(A)\,P(B)$$
- **유도 — 왜 곱하나 (비율의 비율):**
  - 10,000분 중 서버 A가 살아 있는 시간: $10{,}000 \times 0.99 = 9{,}900$분
  - 독립이니까 그 9,900분 동안에도 서버 B는 99% 살아 있다: $9{,}900 \times 0.99 = 9{,}801$분
  - 둘 다 살아 있는 비율: $\dfrac{9{,}801}{10{,}000} = 0.99 \times 0.99 = 0.9801$
  - 즉 $P(A \cap B) = P(A) \times$ (A가 살아 있는 동안 B도 살아 있는 비율)이고, 독립이면 뒤의 비율이 그냥 $P(B)$다. 이 '동안의 비율'은 1-7에서 조건부 확률로 정식으로 다룬다.
- **직렬 구성 (전부 살아 있어야 돌아감):** 서로 독립이면
  $$P(\text{서비스}) = p_1 \times p_2 \times \cdots \times p_n, \qquad \text{가동률이 모두 } p \text{이면 } p^n$$
  1보다 작은 수는 곱할수록 작아진다. 그래서 서버가 늘수록 가동률이 떨어지고 (5대 0.951, 10대 0.904, 100대 0.366), 전체는 가장 약한 하나보다도 낮다.
- **독립이 아니면 곱하면 안 된다:** 서버 5대가 전원 하나에 물려 같이 살고 같이 죽으면, "모두 살아 있다" = "전원이 살아 있다"라서 서비스 가동률은 그냥 0.99다. 9,900분 유도로 보면 A가 살아 있는 9,900분 동안 B도 전부 살아 있는 경우다. 곱셈 공식은 독립일 때만 맞는다.
- **직접 구현 (`mymath/prob.py`):**
  - `series_availability(ps)`: 확률이 0~1 밖이면 바로 `ValueError`를 내고 (가드), 아니면 곱한다.
  - `simulate_series(ps, n, seed)`: n분 동안 `all(rng.random() < p for p in ps)`이면 세고, 마지막에 `up / n`.
  - 수학과 코드의 짝: $P(A) \approx$ 반복한 비율 ↔ `up / n`, $A_1 \cap \cdots \cap A_5$ ↔ `all(...)`, $p_1 \cdots p_5$ ↔ `a *= p`. 테스트 `test_simulation_is_close_to_formula`는 시뮬레이션 값이 곱셈 공식과 맞는지, 즉 독립일 때의 곱셈 공식을 확인한다.
- **문제 풀이:**
  - ★ $0.9 \times 0.9 = 0.81$ · 로봇 3단계 $0.9 \times 0.5 \times 0.8 = 0.36$ · 가동률 0.95인 서비스는 한 달에 $720 \times 0.05 = 36$시간 멈춘다 (멈춘 비율 $= 1 -$ 가동률. 1-4에서 여사건으로 다룬다).
  - ★★ 거꾸로 풀기: 서버 5대로 99%를 지키려면 $p^5 = 0.99$, $p = 0.99^{1/5} \approx 0.998$. 서버 한 대가 멈추는 시간을 한 달 7.2시간에서 약 1.4시간으로, 5분의 1로 줄여야 한다. 분수 지수 $a^{1/n}$은 1-3에서 정식으로 다룬다.
  - ★★ 어디부터 고칠까: 성공률 0.9, 0.5, 0.8인 세 단계 중 하나만 0.1 올리면 전체가 ① 0.40 ② 0.432 ③ 0.405가 된다. 가장 약한 ②를 올려야 가장 많이 오른다. 괄호를 풀면
    $$0.9 \times (0.5 + 0.1) \times 0.8 = 0.9 \times 0.5 \times 0.8 + 0.1 \times (0.9 \times 0.8) = 0.36 + 0.072$$
    늘어나는 양은 $0.1 \times$ (나머지 단계의 곱)이다. 가장 작은 단계를 빼고 남은 곱이 가장 크다. 하나를 조금 바꿨을 때 전체가 얼마나 변하는지는 4-4 편미분에서 정식으로 다룬다.

## 헷갈렸던 점

- 가동률을 "서버가 몇 대 죽어도 트래픽을 받아 내면 가동"이라고 생각했다 → 오늘 문제는 전부 살아 있어야 돌아가는 **직렬** 구성이다. 학습자가 생각한 건 여분을 두는 **병렬(이중화)** 구성이고, 1-4에서 계산한다.
- $0.99^{100}$을 0.9999…(곱할수록 9가 늘어난다)로 예상했다 → 1보다 작은 수는 곱할수록 작아진다. $0.99 \times 0.99 = 0.9801$, $0.99^{100} \approx 0.366$.
- 확률 검사를 `0.0 < p < 1.0`으로 써서 1.0을 거부했다 → 확률은 $0 \le P \le 1$이고 등호가 들어간다. 절대 안 죽는 서버의 가동률은 1이다.
- `rng.random(minute)`라고 썼다 → 괄호 안의 숫자는 뽑을 개수다. 0분째에 빈 배열이 나와 `ValueError: The truth value of an empty array is ambiguous`가 났다. 1분에 한 번 뽑으려면 `rng.random()`.
- 수식을 코드로 옮기기가 어려웠다. 처음엔 플래그와 `break`로 길게 짰다가 `all()`로 줄였다 → 다음부터는 한국어 주석으로 단계를 먼저 적고 한 줄씩 코드로 옮긴다.
- ★★ "어디부터 고칠까"에서 ①을 100%로 만들면 "계산에서 빠지니까" 이득일 것 같았다 → 빠진다는 건 0.9 대신 1을 곱한다는 뜻이고, 전체는 1.11배가 될 뿐이다. ②는 0.5 → 0.6이라 1.2배다. 같은 0.1이라도 작은 수에 더하면 배율이 크다.
- 1-1 복습 (빼는 순서): "정의역이 변할 때 치역이 얼마나 변하는지가 기울기라서"라고 답했다 → 기울기의 뜻은 맞지만, 순서를 바꿔도 값이 같은 이유는 분자와 분모가 **둘 다** 뒤집히기 때문이다. 아래 복습 질문 3번으로 한 번 더 본다.
